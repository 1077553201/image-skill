# Workflow and execution boundary

The interactive entry is product-studio design. Read [design_workflow](design_workflow.md). Inspect assets and existing answers, propose concepts, record user selection, then author individual pages and sketches. Stop for design review. Do not spend generation budget merely to test planning.

Existing product-studio generate and the legacy campaign contract remain low-level tools for older approved requests, not the normal Skill entry. They have no design-session gate themselves. Never invoke them to evade unapproved designs. Current design handoff checks page approval and existing asset gates but submits no task. A later approved-page executor still needs to connect free layers to generation/composition; do not claim it has run.

After execution is authorized and implemented, reuse the immutable ComfyUI workflow, source-bound facts, exact Alpha compositor, type renderer and candidate cache. Preserve graph hashes, prompt IDs, seeds and downloads. Changed designs need new task/cache identities. Do not mutate old results. Legacy --render-only does not submit missing tasks.

Use source viewpoint and uniform scale/translation or real detail crops. No invented wearing, hidden parts, perspective or contact. Concept edits require separate permission. Strict mask approval does not approve final composition. Review actual output against design/source and revise only affected pages.
