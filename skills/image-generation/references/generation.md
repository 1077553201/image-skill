# 两路生图

## 共同边界

一个批次只选 `agent` 或 `comfyui`，先询问并记录用户对最终提示词、路线、候选数量和尝试次数的确认。不可用时说明问题，未经用户选择不切换其他路线、模型或计费服务。不得把用户对 Skill 开发的同意视为具体商品批次的确认。

以批准的版本执行；人物、道具先生成统一参考图并验收，样张完成排字验收后制作其他页。普通页面的新增营销文字通过真实字体排版，不要求图像模型绘制。图片输出自动归档，成功、待检查、失败、远端状态不明分别记录。

提示词表达按 [官方提示词约束](official-prompt-constraints.md) 选用；该文件只有官方方法，不提供当前商品事实或免检模板。

## 参考图职责与生图预检

每个批次参考项只能使用实际 `path` 或已声明的 `from_job`，并记录以下职责信息。按 `references` 数组的实际顺序向生图工具传图，并在提示词中以“第 1 张图……”对应说明，不能只把所有图片笼统称为参考图。

| 字段 | 含义 |
| --- | --- |
| `role` | `product` 商品身份、`person` 人物身份、`prop` 道具、`style` 风格、`composition` 构图、`background` 背景 |
| `target` | 本图约束的具体对象或区域，例如商品本体、character-001、背景光影 |
| `preserve` | 必须保留的特征列表；必须具体到本图职责 |
| `allow` | 用户允许改变或借鉴的内容列表，无可变项时显式写空列表 |
| `exclude` | 不得复制或引入的内容列表，无额外排除时显式写空列表 |
| `priority` | 整数，数值越大优先级越高；商品事实和身份约束不能被风格优先级覆盖 |

商品页必须有 `role=product` 的商品参考图。用户确认页面不出现商品时，页面任务记录 `product_absence_reason` 及确认依据；无商品参考不等于获得自由设计商品的授权。多个身份参考冲突时先澄清，不能选择优先级高的一张来混合型号。风格或构图参考只迁移获准内容，不复制其他商品、文字、标识和未经确认的配件。

首次执行及工作流变化后核实：模型和输入是否支持真实参考图编辑、参考图数量、画幅及尺寸、候选数量、透明或遮罩需求。对 ComfyUI 沿实际节点连线核实每张图片参与了哪个生成或合成环节，仅有 `LoadImage` 节点不能证明商品身份已受约束。对内置工具先确认参考图能按序传入；不满足时提出具体调整，不静默少传图片。

执行 `preflight` 并归档返回结果后再 `run`。预检仅核对批准输入、依赖声明和可验证的工作流结构；执行时仍须确认实际依赖已验收。构图留白、商品比例、光影和商品保真仍须 agent 判断并在实际成图后检查。工具接口见 [运行工具与数据格式](runtime.md)。

## agent 内置生图

使用当前环境中实际暴露的图像生成工具，例如支持生图的 Codex 环境。不同 agent 的能力、输入参考图数量、输出尺寸和额度不同，先检查，不硬编码模型或会员权益。执行工具本身不会调用 OpenAI API、代理或处理登录凭据。

工作方式：`run` 创建待调用记录 → agent 读取执行记录中的 `effective_prompt`（包含展开的参考职责）和按顺序解析的参考图 → 按该生图工具自身要求调用 → 使用 `import-agent` 保存真实输出。调用标识和工具名必须来自实际执行。工具不可用或受限时报告，等待用户调整；不要用本地画图代替模型图来通过验证。

工具要求引用已有图片时必须实际附带输入，不能只在提示词写文件名。编辑生成的底图时保留原图和此次编辑对应关系，重复明确不允许改变的商品特征；“同上”或使用相同种子不能替代参考图。

## 远程 ComfyUI 连接

先读取项目根目录的 `detail-page.connection.json`。没有配置时询问服务器地址，若用户在当前会话已提供地址直接验证使用；不从旧配置或历史报告自动猜地址。验证并保存：

```text
python -X utf8 <runtime> connection --project-root <项目绝对路径> --url <用户提供的服务器地址>
```

该命令只读取 `/object_info` 和 `/queue` 验证连接，然后保存地址、验证时间与节点数；不会提交工作流，不测试生图能力。更换地址后重新执行；连接失败不会覆盖已有配置。此文件是项目连接设置，不放到系统根目录或 Skill 目录。服务器路径和本地项目路径分开，不将 Windows 本地路径直接传给远程 `LoadImage`。

## 工作流配置

先检查实际 `/object_info`，选择服务器已安装且功能相符的工作流。保存 **API prompt 格式**（节点 ID → class_type/inputs）；编辑器的 `nodes/links` JSON 不能直接提交。现有工作流必须确认其模型、参考图编辑能力及用途，背景专用工作流不能冒充商品参考图编辑。

将真实工作流归档到 `06-工作流与执行记录/workflow-api.json`，并依据真实节点编写配置。以下是格式示意，节点名和 ID 都必须由实际工作流替换，不能直接拿来提交：

```json
{
  "workflow": "06-工作流与执行记录/workflow-api.json",
  "output_node": "save-node-id",
  "capabilities": {
    "mode": "reference_edit",
    "model": "实际模型及版本",
    "max_references": 1,
    "supported_sizes": [[1024, 1536]],
    "validation_evidence": "实际工作流来源、参考图通路和已有验证记录；不能凭空声明通过"
  },
  "mapping": {
    "prompt": {"node": "text-node-id", "class_type": "实际编码节点类型", "input": "实际提示词参数"},
    "prefix": {"node": "save-node-id", "class_type": "实际保存节点类型", "input": "filename_prefix"},
    "width": {"node": "size-node-id", "class_type": "实际尺寸节点类型", "input": "实际宽度参数"},
    "height": {"node": "size-node-id", "class_type": "实际尺寸节点类型", "input": "实际高度参数"},
    "reference_0": {"node": "image-node-id", "class_type": "LoadImage", "input": "image"}
  },
  "fixed": {
    "candidates": {"node": "batch-node-id", "class_type": "实际候选数量节点类型", "input": "实际数量参数"},
    "seed": {"node": "sampler-node-id", "class_type": "实际采样节点类型", "input": "实际种子参数"}
  }
}
```

`capabilities` 必需；`mode` 仅为 `background` 或 `reference_edit`。有参考图的任务必须使用经核查的 `reference_edit` 工作流，参考数不超过 `max_references`，尺寸必须在 `supported_sizes` 中。`model` 与 `validation_evidence` 均需非空的实际记录；这些声明及节点通路检查仍不能证明商品保真，最终看图验证。示例为单参考页，人物、多参考或其他尺寸任务要按实际能力另配工作流。

支持动态映射 `prompt`、`negative_prompt`、`width`、`height`、`seed`、`prefix`、`candidates` 和按任务参考图顺序编号的 `reference_0`、`reference_1` 等。`prompt`、`prefix` 和参考图必须动态映射；宽、高、候选数量及任务显式指定的 seed 各需动态 `mapping` 或固定 `fixed` 绑定。`fixed` 使用相同的节点声明格式，工具读取模板中实际值与批准任务逐项比较，不假定模板值恰好正确；同一参数不同时声明两种绑定。示例固定候选数和种子必须已在真实模板中设置为任务对应值，无显式 seed 的任务可省略该绑定。

参考图数量和接口必须适配，每个 `LoadImage` 都需要显式绑定批准的参考图，且沿真实连接抵达输出。其他自定义图像载入节点的行为必须单独检查，不能夹带模板残留的商品图片。

不同任务需要不同工作流或数量不一致的参考图接口时，给对应任务指定 `workflow_config`，选择适配模板并一并确认执行设置。禁止为了跑通而丢弃参考图、变更商品身份或忽略人物道具依赖。

工作流固定尺寸、种子、候选数或输入数量与批次要求不一致时，先修正并重新确认。特别检查被旁路、未连到输出或只在预览支路中的参考图；不能以上传成功、节点存在或接口返回成功代表参考约束已生效。

## 执行与取回

`run` 先验证图和真实节点，再上传本地参考图并校验上传字节，保存实际提交工作流，向 `/prompt` 提交一次。执行目录记录原服务器地址与 `prompt_id`。随后轮询：

```text
python -X utf8 <runtime> resume --task <task> --run <run-relative>
```

每次 `resume` 只检查一次历史。返回 `remote_pending` 时由 agent 适度等待后继续查询，不重复 `run`。工作流成功后核对历史中的图与实际提交图一致，再下载配置输出节点的真实 `output` 图片，检查尺寸和数量后写入本地方案目录。不能将 `input` 或 `temp` 图当成输出。

提交响应丢失时保存 `submission_uncertain`；保留 `submission.json`（若有）、工作流及时间，检查原服务器的队列和历史，先定位原任务。不能直接重新提交或全局中断其他用户任务。原服务器变更地址后，确认确实为同一服务且任务历史仍在，才更新该执行记录的连接地址并继续查询。

生成错误、依赖缺失、超过用户同意的等待时间或尝试上限时报告具体任务与状态，不删除记录或自动启动无限重试。当前工具不会自动更新 ComfyUI、安装自定义节点、接入会员代理或切换付费 API。

## 画面检查与修正

取回真实输出后，先打开候选底图，与批准商品图、人物道具参考和画面要求逐项比较。记录实际商品保护区域与文字可用区域，再使用 `inspect-image` 保存具体观察；看图不通过时先退回，不直接排字。检查记录绑定候选图校验值，编辑或替换底图后重新检查。

通过的底图进入真实字体排版，排字后再检查文案、笔画、对比度、边距、遮挡及整套一致性。工具只做几何和记录检查，不能代替看图，也不自动判定商品身份。

不合格图使用 `reject` 登记：问题区域、预期与实际差异、依据、修改动作、保持项和复查标准。排版问题使用独立新排版版本，经 `approve-layout` 后 `rerender` 复用底图；画面问题才基于已批准范围做局部编辑或重新生成。提示词、参考素材或生成设置变化时另存版本并确认，不能将旧确认用于新要求。具体命令与 JSON 见 [运行工具与数据格式](runtime.md)。
