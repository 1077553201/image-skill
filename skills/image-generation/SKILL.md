# 商品详情页信息图设计 Skill

职责是把用户提供的商品资料转化为可追溯的详情页成品。流程为：建立方案目录 → 完整澄清 → 设计方案 → 用户确认方案 → 编写画面提示词与排版数据 → 用户确认提示词及生图路线、执行范围 → 制作并确认人物和道具参考素材 → 一页样张制作及用户验收 → 批量制作 → 检查归档。用户只要求方案或提示词时，在其指定交付阶段停止。

首次执行归档、生成或排版操作时，阅读 [运行工具与数据格式](references/runtime.md)，使用 `scripts/detail_runtime.py`；工具仅依赖 Python 标准库与 Pillow，不自动安装依赖或修改服务器环境。两路生图的区别和操作要点见 [生图路线](references/generation.md)。

## 新方案目录与持续归档

每次开始新方案时，先从用户指定位置或当前打开的项目识别项目根目录，并将绝对路径显式传给工具的 `init --project-root`。无法确定项目时先询问，不以进程当前工作目录、磁盘根目录或系统目录代替。工具将绑定路径写入 `task.json`；所有分类写入都须通过其路径校验。不要在 Skill 安装目录建立商品项目。目录名采用 `详情页-日期时间-商品简称`，商品尚未命名时用“待命名商品”，同名时增加序号。

根目录不等于 `C:\`、`D:\`、`/` 或用户主目录。不得通过绝对输出路径、`..`、符号链接绕过绑定目录；脚本切换工作目录后仍使用绑定路径。移动整个项目后，先确认新项目根目录并显式更新 `task.json` 的绑定，再继续，不自行猜测新位置。

新方案使用新目录；用户要求修改或继续已有方案时，读取其目录索引并在原目录中保存新版本，不重复建项目，也不只依赖聊天历史恢复上下文。

按以下结构保存实际内容，目录内路径使用相对路径，便于整体移动后引用：

```text
详情页-日期时间-商品简称/
  项目索引.md
  01-原始资料/
    商品资料.md
    素材清单.md
    图片/
  02-需求澄清/
    信息清单.md
    问答记录.md
  03-设计方案/
    方案-v001.md
    确认记录.md
  04-一致性素材/
    素材索引.md
    character-001/
      设定-v001.md
      生成提示词-v001.md
      参考图/
    prop-001/
      设定-v001.md
      生成提示词-v001.md
      参考图/
  05-提示词与排版数据/
    v001/
      page-001-prompt.txt
      page-001-layout.json
      batch.json
  06-工作流与执行记录/
  07-生成结果与检查/
  08-最终交付/
```

示例中的页数、人物和道具数量不固定；仅在实际需要时创建对应素材目录，不创建虚构素材或空白成品文件。

- 将用户原始商品说明和实际可访问的图片保存到原始资料目录；复制图片，不移动或覆盖源文件。素材清单记录原文件名或附件标识、归档路径、图片编号、对应型号和用途。聊天中可见但无法取得原文件时，记录访问限制并请求补充可保存的文件，不伪造路径或声称图片已归档。
- 每轮澄清后保存最新信息清单和问答内容，保留用户原意与答复来源；每次输出方案或提示词时同步写入对应文件，不能只在聊天中展示。
- 方案修改保存新版本；确认记录写明用户实际确认的版本、确认内容与消息标识或确认原文。未经确认不得标记为已确认。
- 项目索引持续记录当前阶段、待解决项、当前及已确认的方案版本、素材版本、逐页提示词路径和依赖关系。交付时提供目录及关键文件链接，便于以后继续使用。
- 提示词新版本另存，不覆盖旧版；标明依据的方案和素材版本。上游方案或素材发生变化时，将受影响的旧提示词标记为待更新，不能默默当作当前版本复用。
- 项目根目录的 `detail-page.connection.json` 仅保存该项目的 ComfyUI 连接信息；方案的 `task.json`、批次确认记录及执行记录保存状态和版本。目录索引链接实际文件，不以空文件或聊天中的路径声明代替归档。

## 接收与完善资料

先阅读用户已提供的图片与文字，再按商品类型整理已知信息与缺口。以下是信息维度示例，不是固定表单，也不要求每件商品都收齐所有字段：

- 商品资料：商品名称、型号或 SKU、规格、功能、材质、使用方式，以及用户提供的证明材料。
- 图片素材：整体、细节、使用场景、包装、不同型号或颜色，并记录各图片对应的商品版本。
- 客户与销售背景：目标客户、需求、使用场景、购买顾虑、销售平台、市场及语言。
- 设计与内容约束：品牌调性、已有素材、参考风格、页面尺寸、页面数量、必讲内容和禁用表述。

可依据商品补充、替换或省略信息维度。例如，服饰可能需要尺码与版型信息，电器可能需要供电与适配信息。不要把某一品类的字段强加给其他商品。

建立信息清单，记录每项信息的内容、来源和状态：已明确、待回答、存在冲突、不适用，或用户确认无法提供并同意省略。将分析中发现的所有缺口逐项纳入清单；不得在提问时把多项具体缺口简化为少数笼统问题，导致遗漏。

针对每个未解决项提出明确问题，说明需要什么信息、会影响哪项设计判断。可以按商品、素材、客户、平台、设计等主题组织问题，也可以分轮询问，但必须覆盖全部缺口，不因问题数量较多而自行跳过。用户已明确回答的信息不重复询问。

每轮收到回答后，逐项更新清单，检查漏答、含糊回答、冲突及新产生的问题，继续追问，直到所有与本次任务相关的信息都已有明确处理结果。仅做资料阅读、初步分析和缺口梳理；存在未解决项时，不进入逐页方案设计或提示词编写。

用户无法补充的事实不得猜测。说明省略会影响哪些卖点或页面，取得用户对省略或调整范围的明确确认后，才将该项视为已解决。设计偏好可提供具体建议供用户选择，只有用户同意采用建议或明确授权 agent 决定后才算明确；该授权不适用于商品事实。

澄清结束时展示已确认的信息摘要及用户同意省略的内容，确认清单中没有尚待回答或存在冲突的事项，再进入方案设计。不要求追问与本商品及本次交付无关的信息。

## 商品事实边界

- 绝对不捏造商品参数、功能、材质、性能、认证、测试数据、销量、评价、售后承诺或其他商品事实。
- 区分用户提供的事实、图片可直接观察到的特征、设计建议和待确认信息。对影响文案的事实记录来源，便于回查。
- 图片只支持可见的外观判断。不得凭外观推断尺寸、材质成分、功率、容量、耐用性、功效或认证。
- 资料相互冲突、图片版本不一致或型号归属不明确时，向用户核实，不擅自选择或拼合不同型号的信息。
- 不将推测包装为卖点，不编造用户痛点、客户评价或竞品比较来证明商品优势。客户需求假设可用于讨论，确认前不得当作已证实结论。
- 设计建议可由 agent 提出，例如配色、排版或阅读节奏；不得借设计补全未知的商品事实。未确认的参数不得写入可直接发布的页面文案。

## 分析与逐页设计

仅在信息澄清完成后执行。

1. 汇总商品已确认的特征、可支持的卖点与素材，结合目标客户及平台背景，说明各卖点回应的需求或购买顾虑。区分事实依据和策划判断。
2. 根据商品和信息量设计页面顺序，解释阅读逻辑。不要预设固定页数，也不要机械套用所有品类相同的页面模板。
3. 制定统一视觉方向：风格、配色、字体层级、留白、商品展示方式、图形语言及跨页一致性。用户没有指定的视觉选择可提出建议并标明。
4. 逐页输出具体设计，明确每页的信息目的、文案、图片和版式，使后续执行者能够据此制作详情页。
5. 盘点各页需要出现的人物、道具、其他物品及重复场景元素，为其分配稳定素材编号，明确哪些跨页复用；将设定与使用页码纳入方案供用户确认。

每页方案应包含：

- 页码、主题与阅读目的：本页需要让客户理解什么，或回应什么顾虑。
- 文案：主标题、副标题、正文、标注及必要说明；按实际需要取舍。
- 排版：内容分区、阅读顺序、文字与图片的位置、大小关系、层级和留白。
- 视觉设计：本页配色、背景、字体层级、图标或辅助图形，并说明如何延续整体风格。
- 图片使用：引用用户提供的具体图片或图片编号，说明展示部位、裁切和构图；缺少素材时明确提出补充需求。
- 事实依据：单独记录用于本页的资料来源及用户确认省略的内容，不混入面向客户的文案。设计过程中发现新缺口时，返回澄清环节，解决后再继续。

按需建议尺寸或比例；平台规范未经核实时，不将建议值称为平台强制要求。所需平台规则无法确认时向用户索取规范；无法取得时，询问是否采用明确标注为设计建议的尺寸或调整交付范围，不带着未解决项继续。

## 方案确认

输出并保存完整方案后，请用户确认页面顺序、各页卖点与文案、排版、统一视觉方向及素材使用，包括人物、道具等辅助素材的设定与复用关系。此处停止，等待用户明确确认，不在同一轮提前附上生图提示词或辅助素材生成提示词。

用户提出修改时，更新方案并再次请求确认。用户明确确认的版本是编写提示词的依据；确认后继续输出逐页提示词，不将方案本身当作任务完成。已经确认的内容无需重复确认，除非发生影响内容或视觉结果的变更。

## 人物与辅助物品的一致性提示词

方案确认后，先为设计中出现的每个独立人物、道具或其他辅助物品编写并保存对应生成提示词，再编写依赖它们的页面提示词。跨页使用同一个对象时复用同一编号与版本，不为每页重新发明形象。已有参考图也要保存其设定和对应参考生成或编辑提示词；标明优先复用现有素材，无需重复生成。

每个素材的设定与提示词应记录：

- 稳定编号、名称、版本、对应方案版本、使用页码，以及已有参考图的实际路径。
- 固定特征：人物的外观、发型、服装及配饰；物品的形状、颜色、材质表现、比例和标识约束。仅填写该对象实际需要的特征。
- 允许变化的内容：姿态、表情、视角、位置或与商品的交互方式，并明确哪些特征不能随页面变化。
- 可独立执行的完整生成提示词：准确复述已确认设定，说明所需视角、构图、背景、光影、风格和应避免的变化，适合先制作统一参考素材。需要多个视角或动作时，保存各变体提示词并引用同一基础设定。
- 状态：只有设定、已编写提示词、已有用户参考图，或后续已生成并确认参考图。提示词文件存在不等于参考图已经生成或已获确认。

辅助素材可以是经用户确认的创意设定，但不可暗示其随商品附赠、属于真实包装清单、代表真实代言或评价，也不得借辅助素材虚构商品规格、适配性或使用效果。涉及这些关系时必须回到资料澄清环节。

在素材索引中列出各对象的设定、提示词、参考图、版本和使用页码。先确认素材提示词及执行设置，再按依赖顺序生成并请用户确认人物或物品参考图，随后将同一参考图用于相关页面。尚未生成的图使用批次中的 `from_job` 声明依赖，不以虚构文件名或路径冒充现有输入。同一 seed 或相同提示词不等于身份一致，必须复用已确认参考图并视觉核对。

## 根据已确认方案编写逐页生图提示词

逐页引用已确认方案的页码与主题，说明所依据的方案版本或确认消息，并为每一页提供独立可复制的完整提示词。严格展开该页设计，不另起一套设计，不擅自改变卖点、文案、页数、版式或风格。

每页交付包含以下内容：

- 方案对应关系：页码、主题，以及对应的已确认方案。
- 参考素材清单：使用的实际图片编号或文件名、对应商品型号、用途，以及需要随提示词一同上传的素材。不引用不存在或尚未取得的素材。
- 一致性素材依赖：列出本页人物、道具等素材编号、设定版本、生成提示词路径及已有参考图路径，区分现有输入与待生成依赖。在本页完整提示词内展开其固定特征和允许的动作变化；不能只写素材编号。依赖未就绪时，说明完成哪些参考图后才能执行本页。
- 画面生图提示词：明确画布尺寸或比例、页面目的、商品展示角度与构图、各区块的位置及占比、配色、背景、光影、图形元素和文字区留白。页面新增标题、正文、参数不交给模型绘制，明确禁止额外文字或伪字；商品原有商标和包装文字须保真，不能简单要求抹除一切文字。
- 准确文案与排版数据：独立保存主标题、副标题、正文、参数和标注，指定字体文件、字号、颜色、位置、文本框、对齐和行距。提示词只描述留白，不将内部备注或整段待排文字混进去。禁止自行增加或改写文案中的参数与承诺。
- 商品保真要求：依据指定参考图保留商品的形态、颜色、结构、标识及型号特征；不得新增部件、混合型号或臆造不可见结构。需要缺失角度或细节时先返回澄清环节。
- 限制条件：写明该页需要避免的商品失真、额外商品、错误文字及与已确认方案冲突的元素。按实际使用工具组织为提示词内约束或独立负向提示词，不假定所有工具都支持负向参数。

每页提示词必须完整复述适用于该页的共同视觉规则，不能只写“风格同上”“按照前述方案”或依赖其他页提示词才能执行。内部资料来源、审批记录及说明不要作为上图文字。

核对所有页面都有画面提示词、排版数据及完整设计说明，并逐项对照已确认方案和事实清单。编写中发现新增事实需求或需要变更设计时，回到澄清或方案确认环节。工具会冻结方案、批次、提示词、排版、字体、已有参考图及工作流的校验值；内容变化后需重新确认对应批次。

## 生图选择与执行确认

在新生图批次执行前，询问使用 **agent 内置生图** 还是 **远程 ComfyUI**，同时说明页数、哪些人物或道具需要先生成、每项候选数量和最多尝试次数。等待用户确认最终提示词、排版及执行设置；记录实际确认消息，不可替用户编造确认。已经明确的选择直接沿用，不每页反复询问；新批次或实质变更时重新明确。

- 内置路线：先检查当前 agent 实际提供的生图能力。例如支持时调用 Codex 内置图片工具；不能把聊天能力当作生图能力，也不能用本地绘图伪造模型输出。工具不可用时报告并等待选择，不自动切换付费 API。
- ComfyUI 路线：无连接配置时询问地址，验证实际节点和队列后保存到项目连接配置。用户在当前会话已提供的地址可以直接验证使用，无需重复询问。地址不写死在 Skill 中；连接失败时解释是连接或节点问题，必要时再询问新地址，不自动猜测。按服务器实际节点准备 API 格式工作流，优先复用已验证模板，不虚构节点或擅自安装依赖。
- 每次执行保存实际路线、确认版本、参考图片、工作流、任务编号、输出、错误及尝试次数。内置路线保存真实工具调用标识与输出文件；ComfyUI 路线上传图片、验证上传内容、提交任务并取回实际输出。
- 先执行人物或道具任务，再制作样张。样张必须完成真实字体排版并获得用户验收，才执行其余页面。在已确认范围和次数内由 agent 连续调用工具，无需每张重复授权。
- 请求超时先查询原任务和队列状态，不重复提交。存在执行中或提交结果不明的任务时不启动下一次尝试；达到尝试上限则报告。生成失败不能以源图、预览图或临时图冒充输出。

本次不实现会员额度代理接入，不提取登录凭据，不自动切到其他服务商或额外付费路线。

## 真实字体排版与验收

正式成品默认先生成无新增营销文字的画面，再以 `render` 使用实际字体排入已确认文案。生成阶段预留文字区域；商品保护区域必须覆盖商品本体及其标识，禁止排字遮挡。需要图像放大或编辑时放在排字之前，排字后不自动进行生成式重绘。

排版工具验证画布尺寸、字形覆盖、文本框尺寸、文字区重叠及商品保护区域。出现缺字、超界或溢出时停止；不得静默删字、截断、改写或缩小已确认字号。按问题调整布局或字体后重新确认受影响内容。字体缺失时先寻找环境中可用且有对应字形的字体，无法解决再请求补充，不擅自安装。

必须视觉检查文字内容与笔画、对比度、留白、商品身份、商标包装文字、人物道具一致性。若有可用 OCR 可辅助比对，但 OCR 通过或接口成功不能代替视觉检查。保存检查结论和失败原因；正式交付只收录检查通过且用户验收的页面，原始画面、排字图及失败尝试保留在生成目录，不能提前移入最终交付。

生成模型重绘过的商品不得宣称像素或身份已保真。要求严格还原时，优先保留原始商品前景并合成；无法验证的创意图保留待确认状态。

## 交付前检查

- 每项商品事实均能对应用户资料或明确的可见证据；全部相关缺口均已解决，无法提供的信息已由用户明确同意省略或调整范围，不能仅标为待确认后继续。
- 页面文案与对应型号、图片和规格一致，没有将设计建议写成商品事实。
- 页面顺序与目标客户的阅读需求相符，每页具备明确的信息重点与可执行的排版说明。
- 整套页面风格一致，客户文案与内部备注分开。
- 用户已确认方案与执行批次；每页都有可独立使用的画面提示词、准确文案和排版数据，内容与方案及商品事实一致。
- 新方案已在项目根目录独立归档，原始资料、澄清记录、方案、确认记录及逐页提示词均已实际保存；无法归档的输入已明确说明。
- 设计中出现的人物和辅助物品均有对应设定与生成提示词，并已保存；各页引用同一编号及版本，待生成参考图与实际已有图片清晰区分。
- 区分澄清中、待方案确认、待提示词和路线确认、素材制作、样张待验收、批量制作、检查中及最终交付。核对批次中全部页面与实际文件，部分完成不标为整套完成；未实际调用工具不宣称已生成。

交付时提供项目目录、样张或最终成品及关键提示词文件链接，说明已完成项、验证状态和剩余问题。遵守各阶段用户确认点，不将用户对 Skill 修改的授权当成对某个商品批次的提示词确认。
